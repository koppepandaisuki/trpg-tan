# Re-dice 事業・技術方針(ココフォリアに勝つために)

最終更新: 2026-10-14

## 1. 勝ち筋の要約

1. **値段で負けない**: 卓のホスト・参加・主要機能は**無料**(ココフォリアと同じ線)。ココフォリアで
   有料(PRO ¥500/月)の「ルーム複製」「書き出し」「タイマー」を**無料**で出す。
2. **機能で上回る**: キャラシ作成・シナリオ執筆(工房)・日程調整・GM 用シナリオパネルまで
   **1 か所で完結**。ココフォリアは外部のキャラシサイトやメモ帳と行き来が必要。
3. **維持費をほぼゼロに**: 卓の通信は GM ⇔ 参加者の **P2P 直結**。サーバーは「つなぐ段取り」と
   「直結できない人の中継」だけ。利用者が増えてもサーバー代が比例して増えにくい。
4. **収益は「快適さ」で**: 無料の人にはロビー等に控えめな広告。有料プランは広告なし・確実接続の
   中継(TURN)・容量など、遊ぶ自由を削らない特典で取る。

## 3. 通信の仕組みと費用

```
GM ──(WebRTC 直結 / DataChannel)── 参加者A
 │ ────────────────────────────── 参加者B
 └─ Supabase Realtime: presence(誰がいるか)・直結の段取り(SDP)・直結できない人への中継
```

- **差分同期**(`packages/trpg-core/src/play/sync.ts`): 変更のたびに卓全体を送っていたのをやめ、
  前回との差分だけを送る。連続した変更は 1 本に集約。駒 1 つの移動は数百バイト。
- **秘密を送らない**: 秘匿駒・その駒の発言・GM メモ・シナリオの秘密・GM だけのシークレットダイスの
  出目は、配信前に取り除く(`projectForPlayers`)。
- **P2P 直結**(`packages/trpg-core/src/play/p2p.ts`): 星形(GM ⇔ 各参加者)。直結できない相手には
  自動で Supabase 中継。旧版のアプリとも混在可。参加者どうしは直結しない(IP を他の参加者に出さない)。
- **計測**(同一 PC の 2 タブ・実ブラウザ): 定常状態の中継メッセージ 0 件、駒の移動が相手の画面に
  出るまで約 5ms。53 回の連続変更が 3 回の送信に集約。

### 費用の目安と上限
| 資源 | 無料枠 | 何で消費するか | 対策 |
|---|---|---|---|
| Supabase Realtime | 同時接続 200・100 msg/s | presence・段取り・中継 | 直結で大半が不要に。超えたら Pro($25/月、同時 500〜) |
| Cloudflare STUN | 無制限・無料 | 直結の準備 | ― |
| Cloudflare TURN | 毎月 1,000GB 無料、超過 $0.05/GB | 有料プランの確実接続 | 有料プラン限定(env を入れたときだけ) |
| **Supabase Storage の転送量** | **月 5GB(Free)** | **BGM・画像を参加者がダウンロード** | **最大のリスク。§5 の R2 移行を推奨** |

## 4. 有料サーバーへの切り替え方(段階)

通信は `RoomTransport` という差し替え口で抽象化してあるので、段階的に上げられる。

1. **今**: P2P 直結 + Supabase Free(段取り・中継)+ 公開 STUN。費用 0 円。
2. **有料プランの特典**: Cloudflare TURN(`CLOUDFLARE_TURN_KEY_ID` / `CLOUDFLARE_TURN_API_TOKEN` を設定)。
   `/api/play/ice` が有料プランの人にだけ短期資格情報を発行する(実装済み)。
   直結できない回線でも速く、相手に IP を出さない。
3. **利用者が増えたら**: Supabase Pro に上げる(コード変更なし)。または段取り・中継を
   Cloudflare Durable Objects(WebSocket)に移す(`lib/play/net.ts` に別アダプタを書くだけ。
   プロトコルは @trpg/core が持っているので、Web とデスクトップの両方がそのまま使える)。
4. 映像・音声通話は扱わないので SFU は不要。

## 5. 素材の配信を Cloudflare R2 へ(実装済み・設定待ち)
- BGM・画像を Supabase Storage の公開 URL から配信していると、**転送量(Free 月 5GB)が真っ先に
  尽きる**(5MB の BGM × 参加者 5 人 × 卓 100 回 = 2.5GB)。
- Cloudflare R2 は**転送量が無料**(保存 10GB まで無料、超過 $0.015/GB・月)。
- 実装: `/api/play/upload-url` が R2 への署名付き URL(種類と大きさを署名に含む。SigV4 は
  `lib/storage/sigv4.ts`、AWS 公式の例題でテスト済み)を発行し、Web・デスクトップがそこへ直接 PUT
  する。env が無ければ従来どおり Supabase Storage。退会時は R2 のファイルも削除。
- **設定手順**:
  1. Cloudflare → R2 でバケットを作る(例 `redice-media`)
  2. バケットにカスタムドメインを付けて公開(例 `media.re-dice.net`)
  3. R2 の API トークン(Object Read & Write、このバケットのみ)を発行
  4. バケットの CORS に、サイトのオリジン(例 `https://re-dice.net`)からの `PUT`(ヘッダー `Content-Type`)を許可
  5. Vercel に `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` /
     `NEXT_PUBLIC_MEDIA_BASE_URL` を入れて再デプロイ(CSP とプライバシーポリシーは自動で追従)
- 既に Supabase に上がっている素材はそのまま使える(URL が変わらないため)。
- さらに先の手: GM が持っている素材を P2P で参加者へ直接送る(サーバーを通らない)。

## 6. ロードマップ(優先順)

| 優先 | 項目 | 理由 |
|---|---|---|
| P0 | リリース手続き(`docs/legal/README.md` §0) | 法的に必要 |
| P0 | 実運用での 2 人テスト(本番 Supabase で GM・参加者を別端末) | 今回は同一 PC と単体テストで検証 |
| P1 | 素材配信の R2(§5)— **実装済み・設定待ち** | 維持費ゼロの最大の穴 |
| 済 | 個別の秘密(シークレットダイスの出目・個別チャット)を相手ごとに暗号化して送る | `secrets.ts` / `seal.ts`。次は HO(ハンドアウト)の個別配布を同じ仕組みに載せる |
| 済 | 卓からの退室(キック) | アプリストア要件の「ブロック」は、アカウント単位のブロック一覧を足せば満たせる |
| 済 | デスクトップ版にも BCDice | タイマー・シナリオパネルはデスクトップ未対応(表示は Web と共通の卓データで持ち運べる) |
| 済 | なりすまし対策(全メッセージに ECDSA 署名・参加コードを GM の鍵から作る) | 偽の GM 配信(卓の上書き・退室・閉卓)や、他人を装った操作を弾く(`auth.ts`) |
| P2 | カード(山札)・マーカー | ココフォリアとの残りの差 |
| P2 | 参加者画面のスマホ最適化 | 参加者の多くはスマホ |
| P2 | サブスク本実装(Stripe。最終確認画面の表示義務に注意) | 収益 |
| P3 | スマホアプリ(Tauri 2 のモバイル対応で apps/desktop を流用 or PWA を Capacitor で包む) | 完成後に着手の予定どおり |
| P3 | 「ココフォリアから引っ越し」(ルームの書き出し zip の取り込み) | 乗り換えの壁を下げる |

## 8. スマホアプリ化のメモ
- すでに `/app` で PWA(デスクトップ版のフロントエンドをブラウザで動かすもの)を配信している。
- ストア配布するなら、課金はアプリ内課金必須・利用者投稿アプリの要件(報告・ブロック・連絡先)・
  プライバシー申告(`docs/legal/README.md` §8)。
- WebRTC はモバイルの WebView(iOS WKWebView / Android WebView)でも使える。
